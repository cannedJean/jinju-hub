# JinjuHub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 진주시 공공데이터를 병렬 수집·정제·병합해 `places.db`를 만들고, 그것을 쓰는 지도+유등 게이미피케이션 웹사이트를 Netlify/Render/Neon에 배포한다.

**Architecture:** 모노레포 3개 하위 시스템. `pipeline/`(오프라인 배치, asyncio 병렬 수집 → SQLite 산출물) → `backend/`(FastAPI, places.db 읽기 전용 + 게시판 Postgres + 날씨/Claude 챗봇) → `frontend/`(Vue 3 SPA, Leaflet 클러스터 지도, localStorage 유등 상태). 하위 시스템 간 계약은 **places.db 스키마(Task A10)** 와 **REST JSON 스키마(Task B2~B4)** 두 가지뿐이다.

**Tech Stack:** Python 3.12 · httpx · tenacity · pydantic 2 · PyYAML · rapidfuzz · selectolax · pytest/respx · FastAPI · SQLAlchemy 2 · Alembic · psycopg 3 · bcrypt · slowapi · anthropic(Python SDK) · Vue 3.5 · Vite 6 · Pinia 2 · Vue Router 4 · Tailwind 3.4 · Leaflet 1.9.4 · leaflet.markercluster 1.5.3 · Vitest · Playwright · GitHub Actions · Render · Netlify · Neon.

**Spec:** 이 파일의 Part A (Task 0 이후 `docs/superpowers/specs/2026-11-04-jinjuhub-design.md`). 실행자는 Part A와 Part B를 모두 읽는다.

**실행 방식(사용자 선택):** Subagent-driven — superpowers:subagent-driven-development로 태스크마다 새 구현 서브에이전트 + 별도 리뷰어, 마지막에 브랜치 전체 리뷰. Phase B는 A10·A12 Step 5 완료 후, Phase C는 B2~B4 완료 후 병렬 트랙으로 진행 가능. 네트워크·사용자 계정이 필요한 단계(Task 0 Step 6·8, A4/A5 Step 1, A12 Step 6~7, B5 Step 5, B7 Step 5, D1~D3)는 메인 세션이 사용자와 함께 수행.

**하위 계획 분할(Scope Check):** 명세가 3개 하위 시스템을 다루므로 Phase A(파이프라인) / B(백엔드) / C(프론트엔드) / D(CI·배포)로 나눈다. 각 Phase는 단독으로 테스트 가능한 산출물을 낸다: A → `places.db`+`report.json`, B → 픽스처 DB로 동작하는 API, C → 로컬 백엔드에 붙는 SPA + e2e, D → 배포 URL. **B는 A10의 스키마와 A12가 만드는 픽스처 DB만 의존**하므로 A10 완료 후 B를 병렬 진행 가능, C는 B2~B4의 응답 스키마 확정 후 병렬 진행 가능.
